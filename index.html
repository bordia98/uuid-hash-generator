The Definitive Guide to UUIDs and Cryptographic Hashes

Universally Unique Identifiers (UUIDs) and Cryptographic Hash functions form the bedrock of data identification, distributed synchronization, and cryptographic integrity across the web.

UUID v4 vs UUID v7: Which Should You Use?

UUID version 4 (RFC 4122) is generated completely randomly. With 122 bits of randomness, the probability of generating a duplicate UUID v4 is essentially zero (\(1 \text{ in } 2^{122}\)). However, because v4 UUIDs are completely randomized, inserting them as primary keys into relational databases (PostgreSQL, MySQL, SQL Server) leads to heavy B-tree index fragmentation, poor write caching, and sluggish query execution.

UUID version 7 (RFC 9562) solves this by prefixing the identifier with a 48-bit Unix timestamp in milliseconds followed by 74 bits of cryptographic entropy. UUID v7 values sort chronologically in natural alphabetical order, giving databases high-speed sequential insertions while retaining global uniqueness across distributed microservices.

Frequently Asked Questions (FAQ)

Are the generated UUIDs truly unique?

Yes. The randomness is generated using crypto.getRandomValues() and crypto.randomUUID(), backed by your operating system's CSPRNG (Cryptographically Secure Pseudorandom Number Generator). Generating collisions would require billions of machines generating billions of IDs per second for thousands of years.

How does client-side file checksumming work?

Using the HTML5 File API and Web Crypto crypto.subtle.digest, your browser streams the file bytes directly through your local CPU. Not a single byte is ever sent to a server or third party.

What is HMAC and why is it used?

HMAC (Hash-based Message Authentication Code) combines a cryptographic hash function with a secret shared key. It guarantees both data integrity and authentication, proving that a message was not tampered with in transit and came from someone with the secret key.
